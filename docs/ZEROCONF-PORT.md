# Zeroconf native port contract

This contract is pinned to Home Assistant Core `cbf2c02c9bff331537c19bff69da8dc11c3fbfbf`. It records the component boundary and observable behavior for a native mDNS/DNS-SD implementation; it does not specify a second network-adapter policy.

## Protocol and pinned dependency

The zeroconf manifest depends on `network` and `api` and pins `zeroconf==0.152.0` (`homeassistant/components/zeroconf/manifest.json:1-12`). The matching [PyPI source distribution](https://pypi.org/project/zeroconf/0.152.0/) was inspected without installing or importing it; its SHA-256 is `8768de190d88124c4f69665c5547f6ae33366024db76007876bbff79cd2509ae`.

The wire contract is mDNS plus DNS-SD: PTR records enumerate service instances; SRV records carry target host and port; TXT records carry service properties; A/AAAA records provide addresses. Use the primary specifications [RFC 6762](https://www.rfc-editor.org/rfc/rfc6762.html) and [RFC 6763](https://www.rfc-editor.org/rfc/rfc6763.html). TXT is length-prefixed key/value data, not a delimited string: the first `=` splits key from value, later `=` characters belong to the value, and a present key without `=` is distinct from an empty value.

## Data and matching

`ZeroconfServiceInfo` exposes `ip_address`, `ip_addresses`, nullable `port`, `hostname`, `type`, `name`, and `properties` (`homeassistant/helpers/service_info/zeroconf.py:14-50`). The discovery conversion reads all addresses using `IPVersion.All`; it selects the first address that is neither link-local nor unspecified as `ip_address`, retains the full ordered address list, and rejects the service if no such address exists (`homeassistant/components/zeroconf/discovery.py:136-167`). The pinned library returns IPv4 addresses before IPv6 and uses LIFO order within each family (`zeroconf-0.152.0/src/zeroconf/_services/info.py:470-481,806-814`). Scoped IPv6 link-local addresses retain `%<interface index>` in the address object/string when the record has a nonzero scope (`zeroconf-0.152.0/src/zeroconf/_utils/ipaddress.py:115-132`); preserve that scope in `ip_addresses` and WebSocket serialization. The preferred `ip_address` skips link-local values, but those values remain in `ip_addresses` when another usable address exists.

`decoded_properties` preserves property-key case, decodes keys as ASCII with replacement and values as UTF-8 with replacement, and preserves a valueless property as `None` (`zeroconf-0.152.0/src/zeroconf/_services/info.py:710-715`). Home Assistant then matches property keys exactly, rejects missing/`None` values, lowercases candidate values, and applies a case-sensitive `fnmatch`-translated pattern as written (`discovery.py:70-96`). Service-name matchers similarly compare `info.name.lower()` against the unmodified pattern (`discovery.py:398-407`). For effective case-insensitive matching, manifest patterns therefore need lowercase spelling; do not silently change key matching or normalize patterns in the Rust port. A matcher with only its target `domain` matches every instance of that service type.

The generated `homeassistant/generated/zeroconf.py` table supplies built-in service-type matchers and a separate HomeKit model table (`:6-35,309+`). At runtime the loader copies the generated map, appends custom integration manifest matchers, and supports old top-level `macaddress`, `model`, and `manufacturer` keys by moving them under `properties` and lowercasing their values (`homeassistant/loader.py:219-219,289-295,569-619`). A matcher can specify `domain`, optional `name`, and optional `properties`; the manifest `type` selects the service-type bucket.

HomeKit is a special path: the browser always includes `_hap._tcp.local.` and `_hap._udp.local.` as well as `_home-assistant._tcp.local.` even when those types are absent from the generated matcher map (`discovery.py:32-38,215-229`). Model matching checks `md`, then `MD`, exact/prefix model entries split at spaces or hyphens, then case-sensitive wildcard patterns (`discovery.py:50-66,110-133`). A matched model creates a flow for the registry-mapped integration domain with source `homekit`; it does not force the target to `homekit_controller`. The subsequent ordinary zeroconf matcher path is kept only for paired integer `sf=0` devices or models marked `always_discover` (`discovery.py:362-426,99-107`; `loader.py:674-713`). A valueless `sf` raises an uncaught TypeError after that HomeKit flow has already been admitted; preserve that ordering when containing the native error.

## Browser, cache, and removal lifecycle

One `ZeroconfDiscovery` browses the generated service-type keys plus the special HomeKit and Home Assistant types. The library callback is `(zeroconf, service_type, name, state_change)` with Added, Updated, and Removed states. For Added/Updated, Home Assistant creates `AsyncServiceInfo`; a complete cache hit is processed immediately, otherwise an owned background lookup calls `async_request` with `REQUEST_TIMEOUT = 10000` ms (`const.py:11-18`; `discovery.py:264-332`). Update listeners are notified before address validation or manifest matching, so they can observe the raw service even when it cannot open a config flow (`discovery.py:335-346`).

After conversion, each matching integration receives a config flow with original zeroconf data, source `zeroconf`, and `DiscoveryKey(domain="zeroconf", key=(service_type, instance_name), version=1)`. A HomeKit match uses source `homekit`; ordinary flows also receive `alternative_domain` when HomeKit supplies one (`discovery.py:355-426`). Removing a service does not remove a configured integration: it clears any corresponding duplicate-instance repair state, dismisses active zeroconf discovery flows whose `name` equals the removed instance name, and notifies removal listeners with the name only (`discovery.py:243-261,264-295`). If a config entry is later removed, the discovery observer replays its version-1 `(type, name)` key through the cache/lookup path (`discovery.py:243-254`).

The runtime owns one shared zeroconf instance in `hass.data`; the HA wrappers make client `close()` calls no-ops and expose the real close for HA shutdown (`__init__.py:94-112`; `models.py:9-26`). Discovery cancels its browser at `EVENT_HOMEASSISTANT_STOP`, while the shared manager closes at `EVENT_HOMEASSISTANT_CLOSE`, after integrations have had a chance to send goodbye records (`__init__.py:103-109,183-194`; `discovery.py:215-240`). Constructor attempts by integrations are redirected to the shared instance and logged (`usage.py:12-34`). Native callers should borrow the shared manager; they must not create or close private copies.

Network setup is supplied by the `network` dependency: the component reads loaded adapters and enabled source addresses, chooses the library IP version and interface list, and obtains advertisement addresses through the existing network helpers (`__init__.py:116-158,281-288`). Its IPv4/IPv6 choice depends on platform dual-stack support and enabled adapters. Keep adapter discovery and address selection in the Network port; consume its source-address and announce-address results here.

## Local advertisement and configuration compatibility

The local service type is `_home-assistant._tcp.local.`. Its instance name is `<location>._home-assistant._tcp.local.` (location defaults to `Home`, dots become spaces, and the label is truncated to at most 63 UTF-8 bytes); the host is `<instance UUID>.local.`, the port is the HTTP server port, and advertised addresses come from Network. Properties are `location_name`, `uuid`, `version`, `external_url`, `internal_url`, and legacy `base_url` (external URL if present, otherwise internal); unavailable URLs become empty strings. String property values longer than 230 UTF-8 bytes are replaced with empty strings. Registration happens once the frontend/start callback runs and passes `allow_name_change=True` (`__init__.py:199-288`).

The component schema still accepts deprecated `default_interface` and `ipv6` booleans; `ipv6` has schema default `true`, and `DEFAULT_DEFAULT_INTERFACE` is declared `true` but unused. `DEFAULT_IPV6` only supplies the schema default. `async_setup` does not read these values; effective interface and IP-family selection comes from Network/platform state. Preserve validation and legacy acceptance, but do not make these fields drive new runtime behavior (`__init__.py:34-60,126-158,161-196`). The explicit `ALLOW_EXTRA` is on the outer root schema; the inner `zeroconf` schema only declares these two optional fields.

For Home Assistant's own instance ID, a discovered Home Assistant service at disjoint IPs with the same UUID raises a nonpersistent duplicate-instance repair issue; an overlapping local address is treated as mDNS reflection, and a changed/dropped conflicting instance clears its issue (`discovery.py:429-483`).

## WebSocket surface and native API boundary

The component exposes one user-facing command: admin-only `zeroconf/subscribe_discovery`. The incoming command has exactly `id` and `type`; `id` must be a positive increasing integer on that connection. There are no component REST routes or services (`websocket_api.py:28-30,153-161`; inherited validation in `homeassistant/components/websocket_api/decorators.py:134-164` and `connection.py:272-329`). It registers listeners before sending the result, then sends a cache snapshot by resolving PTR records for the generated `zeroconf_types`. An add event contains `{name,type,port,properties,ip_addresses}`; a remove event contains `{name}` only. Updates are sent only for types in `zeroconf_types`; the initial cache scan likewise walks those types (`websocket_api.py:33-43,72-150`). Unsubscribe/connection close removes both listeners.

The native SSDP dispatcher is source-specific today (`crates/hass/src/discovery.rs:50-122,143-180`). Extend its action boundary instead of encoding mDNS identity as SSDP fields: pass the target integration domain, `source`, typed `DiscoveryKey`, and untouched service-info data for flow creation; provide a separate service-update/remove observer carrying the full update record and name-only removal event for the WebSocket contract. Keep the zeroconf discovery key `(type, name)` distinct from the target integration domain. Follow the existing weak-sink/strong-host pattern: `DiscoveryDispatcher::sink()` captures `Weak<Inner>`, while `SsdpHost` owns the dispatcher (`crates/hass/src/ssdp.rs:38`). The zeroconf integration/runtime should strongly own the shared mDNS manager, browser, and cancellable resolver task set; callbacks and subscription handles use weak manager references and explicit unsubscribe guards. Cancel the browser on stop, cancel and join owned resolution/snapshot tasks on teardown, and close the shared mDNS manager only at final runtime close.

## Existing evidence and acceptance falsifiers

Pinned tests cover matcher success/failure and legacy properties, HomeKit prefix/wildcard matching, invalid names, non-UTF-8 properties, IPv4 preference/IPv6 and link-local/unspecified address filtering, removed and protected discoveries, rediscovery, interface selection, duplicate-ID repair, and the WebSocket snapshot/subscription (`tests/components/zeroconf/test_init.py:202-998,1024-1024,1249-1278,1386-1458,1556-1738`; `test_repairs.py:66-197`; `test_websocket_api.py:32-201`). These tests were inspected, not run.

Before accepting a native port, add future-only tests with synthetic DNS records or loopback mDNS datagrams for: PTR→SRV/TXT→A/AAAA resolution and cache-hit versus 10-second request path; Added/Updated/TTL-or-goodbye Removed callback ordering; a scoped IPv6 link-local address surviving into serialized `ip_addresses`; IPv4-before-IPv6 selection and all-link-local rejection; TXT boolean/empty/duplicate/non-UTF-8 values and exact key/pattern case behavior; wildcard matcher and legacy-key parity; HomeKit paired/model behavior; protected discovery dismissal and config-entry-key rediscovery; UTF-8 byte-length advertisement limits and allow-name-change handling; admin denial, exact WebSocket schema, cache snapshot, add/remove events, and listener teardown; and task cancellation plus shared-manager close ordering. No device, multicast LAN, or external service traffic is part of acceptance.
