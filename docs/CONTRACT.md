# Rust runtime contracts

This is the shared contract for the first native Rust implementation. Full Home Assistant parity remains the target; the implementation below is a bounded first milestone. Python integrations and the official frontend cannot run in this runtime.

## Ownership and source

The primary owns the workspace manifest, application crate, documentation, integration, Git operations, and final checks. Workers exclusively own their assigned crate. Workers do not edit another crate, commit, push, change dependencies in the root manifest, or spawn workers. Escalate contract changes to the primary.

Baseline: `home-assistant/core` dev commit `cbf2c02c9bff331537c19bff69da8dc11c3fbfbf`. Read reference code with `git show upstream/dev:<path>`. The `rust-rewrite` branch retains the upstream snapshot as a parent; the upstream implementation remains on the fork's `dev` branch.

## hass-core

All types below are public, serde serializable/deserializable where meaningful, cloneable, thread safe. Use `serde_json::Map<String, Value>` for objects and `chrono::DateTime<Utc>` for timestamps. Public constant `VERSION = "0.1.0-rust"` identifies this implementation honestly.

`Context { id: String, parent_id: Option<String>, user_id: Option<String> }`; Default creates a fresh UUID. `State { entity_id: String, state: String, attributes: Map<String,Value>, last_changed, last_updated, last_reported: DateTime<Utc>, context: Context }`. `Event { event_type: String, data: Map<String,Value>, origin: String, time_fired: DateTime<Utc>, context: Context }`. `StateChange { state: State, created: bool, changed: bool }`.

`Error` implements std Error and variants `InvalidInput(String)`, `NotFound(String)`, `Storage(String)`, `Service(String)`. `type Result<T> = std::result::Result<T, Error>`.

`trait Store: Send + Sync` methods: `load_states(&self) -> Result<Vec<State>>`; `put_state(&self, state: &State, event: Option<&Event>) -> Result<()>`; `remove_state(&self, entity_id: &str, event: &Event) -> Result<()>`; `append_event(&self, event: &Event) -> Result<()>`; `history(&self, entity_id: &str, start: DateTime<Utc>, end: DateTime<Utc>) -> Result<Vec<State>>`. State+event writes are atomic. No event means a reported state whose value and attributes did not change: persist current state without adding history. Expose `MemoryStore::default()` for consumers/tests.

`Runtime` is a cheap Clone of shared internals. Methods: `new(Arc<dyn Store>) -> Result<Self>`; `states(&self) -> Vec<State>` sorted by entity_id; `get_state(&self, entity_id: &str) -> Option<State>`; `subscribe(&self) -> tokio::sync::broadcast::Receiver<Event>`; `set_state(&self, entity_id: &str, state: &str, attributes: Map<String,Value>, context: Context, force_update: bool) -> Result<StateChange>`; `remove_state(&self, entity_id: &str, context: Context) -> Result<bool>`; `fire_event(&self, event_type: &str, data: Map<String,Value>, context: Context) -> Result<Event>`; `history(&self, entity_id: &str, start: DateTime<Utc>, end: DateTime<Utc>) -> Result<Vec<State>>`.

Validate entity IDs (lowercase domain.object_id, ASCII letters/digits/underscore, nonempty components) and state length <=255 characters. Preserve last_changed when the state value is unchanged, last_updated unless value/attributes change; always update last_reported. Exception: force_update refreshes all three timestamps, matching pinned upstream core.py:2527-2529. Persist before mutation/event delivery, and serialize state writes so publication follows mutation order. A state_changed event contains entity_id, old_state (null for creation), new_state (null for deletion). Return storage failures, never publish successful changes when persistence failed.

`ServiceCall { domain: String, service: String, data: Map<String,Value>, target: Map<String,Value>, context: Context }`; `ServiceResult { changed_states: Vec<State>, response: Option<Value>, context: Context }`. `type ServiceHandler = Arc<dyn Fn(&Runtime, &ServiceCall) -> Result<ServiceResult> + Send + Sync>`; `Runtime::register_service(&self, domain: &str, service: &str, description: Value, handler: ServiceHandler) -> Result<()>`; `Runtime::call_service(&self, call: ServiceCall) -> Result<ServiceResult>`; `Runtime::services(&self) -> Value` (object domain -> service -> description). Release registry locks before calling handlers. Parent application supplies native helper services. No callbacks under the state lock.

## hass-storage

Primary review addition: a Store instance may belong to one Runtime cache at a time; Runtime clones share it. Duplicate construction fails rather than allowing stale-cache rollback. Disk SqliteStore holds an exclusive OS lock for its canonical database path (cooperating writers only); direct external SQLite tools must not write to a live store. Restore validates payload IDs/lengths and agreement with current-state row keys. Schema checks include required key/null/default/autoincrement/range constraints.

Expose `SqliteStore::open(path: impl AsRef<Path>) -> hass_core::Result<Self>` and `SqliteStore::in_memory() -> Result<Self>`. Implement Store with Mutex<Connection>, schema migration via user_version, foreign schema refusal, atomic state/history/event writes, index on entity_id+time, WAL for disk stores, bounded busy timeout. Preserve current states on restart. Query history in chronological order, inclusive start/end; invalid time range returns InvalidInput. No raw SQL interpolation. Focused tests: reopen, concurrent writes, deleted current state but retained history, transaction rollback/corrupt schema. Blocking interface is explicit; consumers must use spawn_blocking when calling it on an async request path.

## hass-automation

Expose `Automation` (Deserialize/Serialize), `validate(&[Automation]) -> hass_core::Result<()>`, `start(runtime: Runtime, automations: Vec<Automation>) -> Result<AutomationEngine>`, and `AutomationEngine::shutdown(self).await`. Engine subscribes before returning, with clean cancellation and no detached worker on shutdown.

Configuration uses a documented strict subset of familiar YAML: `id`, optional `alias`, `triggers` (state or event), optional `conditions` (state or numeric_state), `actions` (service calls and bounded delays). Support HA modern `trigger: state/event` and `action: domain.service` syntax; document actual shapes in crate-level examples and README handoff. Reject unsupported options instead of silently ignoring them. Trigger context becomes the service context's parent, preserve user identity. Prevent re-entry loops and bound active work; do not silently drop lagged events. Tests prove state -> condition -> service action, event trigger, invalid config, shutdown, and loop prevention.

## Native helpers (application module)

`crates/hass/src/helpers.rs` is an independent worker scope. Expose `Helpers: Clone + Debug + Default + Deserialize` with public `input_boolean`, `input_number`, `input_text`, `input_select`, `counter` maps keyed by object_id; each value is a strict per-helper Deserialize config. Root app flattens Helpers and separately rejects unknown root keys. Expose `Helpers::validate(&self) -> hass_core::Result<()>` and `setup(runtime: &Runtime, helpers: &Helpers) -> hass_core::Result<()>`. Root app owns all other files in hass crate. Public config struct names are not constrained; callers use Helpers as one value. Validate names, ranges, finite numbers, unique nonempty options; preserve persisted state when present and only initialize missing state. Publish metadata attrs. Register real in-process services for configured helpers: booleans on/off/toggle; numbers set/increment/decrement; text set; selects option/next/previous; counters increment/decrement/reset/set_value. Require explicit known helper entity targets (string/list in target or service data); reject unknown entities, bad values, unsupported device/area targets and mixed invalid batches before changing any helper. Serialize read/modify/write helper service calls (one shared lock is sufficient); avoid deadlocks in forwarding homeassistant.turn_on/off/toggle. No simulated device services or physical traffic. Focused unit tests cover persistent state restore, service target validation, bounds, concurrent increments, and metadata.

## hass-api

Expose `ApiState { pub runtime: Runtime, pub access_token: String, pub config: Value }` and `router(state: ApiState) -> axum::Router`. HTTP authenticated Bearer token except `/health` and WebSocket upgrade (auth inside socket). Reject empty configured token. Avoid token logs, query-string tokens, permissive CORS, fake upstream version. Use constant-time token comparison. Limit body size and sockets. Run synchronous Runtime work in spawn_blocking; do not block Tokio workers with SQLite.

REST subset: GET `/api/`, `/api/config`, `/api/states`, `/api/states/{entity_id}`, `/api/services`, `/api/events`; POST and DELETE states (201 create /200 update /404 absent, Location on state writes); POST `/api/events/{event_type}`; POST `/api/services/{domain}/{service}`; GET `/api/history/period` and `/api/history/period/{timestamp}` with filter_entity_id/end_time. Document unsupported query options and errors. Plain JSON state changes do not control devices. Unknown services fail. Return JSON error status 400 invalid input, 404 absent, 500 persistence, with sanitized messages. Public health discloses only running status.

WebSocket `/api/websocket`: auth_required -> auth -> auth_ok or auth_invalid/close; timeout and maximum frame size; monotonically increasing positive integer command IDs. Implement ping/pong, get_states, get_config, get_services, subscribe_events (optional event_type), unsubscribe_events, fire_event, call_service. Results use HA success/error envelopes, subscriptions emit event envelopes. Subscribe receiver before acknowledging to avoid lost updates, report lag (do not silently skip). Bounded per-socket subscriptions and cleanup on close. Tests exercise real socket authentication, subscription/state/service round trip, validation, and disconnect cleanup. Unsupported commands return unknown_command.
